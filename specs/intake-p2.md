# Spec: intake-p2 (Phase 2 — Intake expansion)

Parent docs: `PRODUCT.md` § Phase 2, `WORKPLAN.md` row P2, `UX.md` J1. Ships J1 complete: share a TikTok/YouTube link or a cookbook photo from the phone, get a reviewable recipe card with the source video attached. No Instacart dependency anywhere in this phase.

**Intent.** Today intake is paste-a-URL-on-desktop for article-shaped pages. P2 makes capture effortless from the phone: share a TikTok or YouTube recipe → the caption/description is extracted into a card with the original video embedded for cooking along; photograph a cookbook page → same card; an iOS Shortcut makes "share → app" a two-tap gesture. Extraction stays honest: caption-thin videos fail gracefully instead of hallucinating, and shaky fields keep their low-confidence flags through review.

**Acceptance criteria.**
1. Paste/share a TikTok or YouTube URL → extraction uses the video's caption/description text (plain HTTP fetch, no media download, no browser automation); the original video renders in review and in cook mode via a sandboxed iframe we construct from `{provider, video_id}` — provider `embed_html` is never stored or rendered (XSS surface; reviewer finding 1).
2. A caption that doesn't carry a recipe (e.g. "link in bio!", pet videos) → graceful "couldn't extract" with zero fabricated ingredients; the message says why (caption doesn't contain the recipe).
3. Instagram URLs → immediate honest failure naming the limitation (login-walled; no oEmbed without FB app review), not a timeout or hallucination.
4. Photo intake: upload a photo of a cookbook page/recipe card on /recipes/new (file input; mobile share sheet reaches it via camera roll) → same StructuredPlan review flow, low-confidence flags intact; oversized images rejected with a clear message (cap documented in code).
5. /recipes/new?url=<shared-url> auto-starts extraction on load — this is the Shortcut bridge. A documented 2-step iOS Shortcut (receive share → open that URL) lands the user on the review card in one gesture. README carries the Shortcut recipe.
6. StructuredPlan v2: additive optional `source_embed {provider: "tiktok" | "youtube", video_id, thumbnail_url?}`; v1 plans still parse/save/cook everywhere (cart builder, cook mode, rebuild untouched — verified: no code branches on plan_version today); the UI field whitelist and server re-validation both round-trip the new field (the two silent-drop points from orientation).
7. Extraction eval extended: golden fixtures for a TikTok caption recipe and a YouTube description recipe; failure fixtures for a caption-less video and an Instagram URL. Same grounding assertions (no hallucinated ingredients) as P1.

**Non-goals (P2).** Nutrition estimates (J1's "nutrition" element rides P3's calorie-budget work; named deferral, not an omission). Voiceover/transcript extraction and any media download (platform gray zone; caption-only until a compliant path exists). Instagram support. Native app / Expo wrapper (Shortcut bridge only, per PRODUCT.md § web-first). Cook-mode timers and per-step video anchoring (embed shows whole video; step-level anchoring is later polish). Auth on extraction endpoints (P4; but flagged: public LLM endpoints must gain a shared-secret gate before the unit-7 production deploy — separate task). Rate limiting. Multi-photo/batch intake.

**Orientation findings (compact).** Adapter seam: `extractRecipe` (lib/extract.ts:85) hardcodes fetch-HTML between SSRF guard and input prep — factor "acquire input" into per-host adapters; `ModelCall` is `(input: string)` and must widen to content blocks for vision (extract.ts:63,77). Rubric is byte-static for caching but cache is currently inert (under Haiku's min prefix) — rubric growth is free; model `claude-haiku-4-5` supports images. Embed ref rides inside `library.plan` JSON (no DDL change; `migrate()` has no ALTER path — db.ts:56). Two independent silent-drop points for any new plan field: UI whitelist (app/recipes/new/page.tsx:37-45) and server re-validation (app/api/recipes/route.ts:32). No auth surface exists (HOUSEHOLD_ID hardcoded in 7 routes). Live probes (2026-07-25): TikTok oEmbed open (title/author/embed_html/thumbnail); TikTok page GET returns full caption in `__UNIVERSAL_DATA` JSON (`"desc"`); YouTube oEmbed open; Instagram oEmbed 400s without FB app token. Compliance rails: CLAUDE.md bans browser automation, not HTTP GET; PRODUCT.md:121 accepts the TikTok enforcement-risk gray zone.

**Decomposition (commit-sized units, in order).**
1. **Adapter seam + StructuredPlan v2:** refactor extractRecipe into acquire-input adapters (default web-html unchanged); add `source_embed` optional field, plan_version 2, round-trip through parse → UI whitelist → server re-validation → library; v1 back-compat test.
2. **TikTok + YouTube adapters:** caption/description acquisition (plain GET + JSON dig, oEmbed for embed ref), thin-caption graceful failure, Instagram recognized-and-refused; unit fixtures from real captured pages.
3. **Embed display:** review page and cook mode (its ingredients screen) render `source_embed` when present, as a sandboxed iframe built from provider + video_id (no third-party HTML). No new recipe-detail route (cookbook links straight to /cook/[id] today; a detail page is not this phase).
4. **Photo intake:** vision content-block path (`ModelCall` widening), upload UI on /recipes/new, size cap, eval fixture.
5. **Share bridge + eval + docs:** `?url=` auto-extract, Shortcut recipe in README, golden-set extension (criterion 7), spec close-out.

**Test strategy.** Unit: adapter dispatch, caption dig from captured fixture HTML, v1/v2 round-trip, size-cap rejection. Eval (RUN_INTEGRATION): 2 new golden fixtures + 2 failure fixtures, grounding assertions unchanged. Live-verify: real TikTok URL end-to-end on dev server (extract → review with embed → save → cook mode shows video); photo of a real cookbook page; Shortcut simulated via `?url=` open.
